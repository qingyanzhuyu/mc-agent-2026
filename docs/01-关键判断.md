## J1 · 动作互斥 + 同步阻塞 ⇒ 并发只能用来"想"，不能用来"做"

> **2026-11-14 补注（实测 + 官方口径）**：并发上限比原先假设的更紧——**比赛期每组仅 2 路**（可能 1 路），
> 且单流实测仅 **21–26 tok/s**。所以本条的结论要加一句：**不只是"并发只能用来想"，而是"能想的次数本身很有限"**。
> 一次 300 token 的决策约 12 s，含一次重问约 24 s；8 小时理论决策上限约 1200 次。
> 这进一步支持 J11（确定性技能推进）：能不进模型的步骤就不要进模型。

- **依据**：规范 §0「同一时间只能执行一个动作，重复调用返回 `busy`」；§4 所有动作都是阻塞式（`move_to` 走完才返回）。
- **影响**：24 路并发的真实用途只剩两个——**分支预演**和**多 planner 草拟**。正确形态是"发动作 → 阻塞等 → 等待期间在另一个线程算下一步"，把 LLM 延迟藏进动作耗时里。
- **推翻条件**：主办方放开多 bot / 多角色同时在线（见 J9 与 Q1）。

## ~~J2 · 计分的"进度树深度"是复利的 ⇒ 押主线链~~ 【已作废 2026-11-13】

> **作废原因**：`RULES.md` v2 草案明确「每项的分值**只由难度等级决定**」，深度项被删除。
> 这条判断连同它推导出的"五段推进/结构分排序"全部失效，见 **J14**。
> 原文保留在下面，只作为记录。

- **依据**：`单项分 = 难度基础分 + 5 × 深度`。一条 15 级的主线链，光深度项就贡献 `5×(1+…+15) ≈ 600` 分，且链上每个节点**各自**计分。
- **影响**：推 story 主线（木→石→铁→钻→下界→烈焰棒→末影珍珠→要塞→末影龙）大概率是最高性价比；散点捡浅层项在归一化后接近 0。
- **推翻条件**：计分表发布后，若深链节点的难度基础分被压得极低、或主线在接口上不可达（如无鞘翅导致某些节点做不了）。
- **11-12 审校补充（@de7provincien-c）**：原版进度树分为 `story` / `nether` / `end` / `adventure` / `husbandry` 五棵独立树，细则明定"深度从各分类根节点起算，根节点深度 0"，因此资源获取链（跨主世界→下界→末地）不等于单一分类树内连续累加到 15 级深度，且线性归一化不会使中浅层确定性支线归零；具体修正见 **J12**。

## J3 · 死亡循环是唯一的一票否决

- **依据**：规范 §7「60 秒内死亡 3 次，bot 自动下线 5 分钟」+ 不补时。
- **影响**：Safety 闸的优先级必须高于任何计划；`deaths_in(60) >= 2` 就进 safe_mode。
- **推翻条件**：主办方承诺死亡不计入或可申请补时（目前明确说不补）。

- **依据**：群里"不用管那个文档里面写的"、"d4.1f 额度有限"、"建议用 qwen 无限额度"。
- **影响**：凡是基于 8M/1.5M 做的预算设计（v1 文档那一整节）全部作废；不要再做 token governor 作为核心模块，改做**速率治理**。
- **推翻条件**：主办方发布正式公告重申统一模型与硬额度。
- **11-12 审校补充（@de7provincien-c）**：群聊放宽尚未写入正式书面规则，且 `d4.1f` 仍注明额度有限；不应彻底删除预算统计与上限熔断能力，而应降级为**可配置开关（默认不熔断、仅记账）**，见 **J13**。

## J5 · 40 分工程评审是最稳的分数

- **依据**：评分项是"完善性 / 新颖性 / 清晰度 / 稳定性·可复现性 / 可维护性"——前两项主观，后三项完全可以靠纪律拿满。
- **影响**：日志、结构、文档从 D0 就要做，不能留到最后；11/18 若有落后，优先保工程分而不是多刷 5 分游戏分。
- **推翻条件**：评委会明确按"游戏内表现"折算工程分。

## J6 · 接口是"高层技能库"，所以比赛本质是 planner + 状态机

- **依据**：`/attack` 自动追打、自动换武器、自动捡掉落；`/shoot` 自带弹道与提前量；`/window/act` 覆盖箱子/熔炉/附魔/酿造/村民。
- **影响**：**不是**写物理 bot，也不是比模型操作精度。差异化只在"任务编排 + 资源规划 + 异常恢复"。工程量比想象小，策略占比比想象大。
- **推翻条件**：正式版接口降级为低层控制。

## J7 · 能力上限被三条限制钉死，别在高成本项上赌

- **依据**：无矿透（只给暴露方块，radius ≤ 64）、无鞘翅、无逐 tick 控制。
- **影响**：挖矿类、长途探索、精确建造的边际成本极高。8 小时里应该把时间花在"接口擅长的事"上。
- **推翻条件**：正式版放宽 `radius`、开放矿透或提供传送。

## J8 · 延迟是重尾分布 ⇒ 必须有超时/降级/队列

- **依据**：实测同一句话请求出现 1.3s / 31s / 58s / 118s；LLM 端点 4 路并发时 2 路被排队近 2 分钟。
- **影响**：任何"同步等模型回话"的写法都会在比赛里随机卡死。必须：动作期间预取、超时降级到 thinking-off、脚本层用当前任务顶着跑。
- **推翻条件**：正式 key 隔离后延迟稳定（届时可简化，但别删掉兜底）。

## J9 · 参考实现会抬高地板，差异化必须来自它没有的东西

- **依据**：群里承诺"后续会提供 harness 参考实现，可以在此基础上优化，也可以从头重构"。
- **影响**：如果大家都 fork 同一份，"工程评审 40 分"实际在评"你在参考实现之上加了什么"。需要主动准备这块叙事（我们加了什么、为什么）。
- **推翻条件**：参考实现不发了，或评审明确不考察此维度。

## J10 · 8 小时单次机会、不补时 ⇒ 稳定性 > 聪明

- **依据**：细则"因参赛程序、网络连接或模型服务造成的中断仍计入比赛时间，不另行补时"。
- **影响**：一次开局崩溃 = 丢掉 60 分里的大头。checkpoint、重连、幂等动作的优先级高于任何策略优化。
- **推翻条件**：主办方改为多轮取最好成绩。

## J11 · 决策粒度采用"确定性技能推进基础生存 + 模型选目标与异常诊断"（@de7provincien-c 2026-11-12）

- **依据**：J8 实测 LLM 延迟存在 31s–118s 重尾；若采用"每一步原子 API 调用都等模型输出"，单套木→石→铁 50+ 步会被尾延迟拖慢数十分钟且单步错参率累乘；而 NMO 接口本身已是高层语义动作（J6）。
- **影响**：砍树、挖石、烧铁、进食、夜间避险等高频生存流程由 `skills/` 确定性状态机闭环执行；LLM 仅在**选择下一阶段目标、处理 `Replan` 异常诊断、复杂特殊场景**时介入。即使模型服务临时超时或中断，Agent 仍能自主推进当前生存技能而不原地罚站。
- **推翻条件**：正式赛 LLM p99 稳定 < 1.5s 且长程零幻觉，或官方参考实现实测证明纯逐动作 LLM 在 8h 内总分与存活率显著更高。

## J12 · 资源依赖链 ≠ 各分类进度树父子深度 ⇒ 主线设止损线并配齐确定性支线（@de7provincien-c 2026-11-12）

> **2026-11-13 补注**：本条"依据"里的深度论证随 J2 一起作废（v2 草案取消深度计分）；
> 但"设止损线 + 配确定性支线"的**做法仍然成立**——只是理由从"深度复利"变成"单价 × 可完成性"。

- **依据**：初赛细则明确进度树深度从各分类根节点起算（`story`、`nether`、`end`、`adventure`、`husbandry` 根节点深度均为 0），跨维度推进会切换分类树而非在单树深度上无限叠加；同时 `本人原始分 ÷ 最高原始分 × 60` 是线性比例，稳拿多条确定性支线的原始分同样直接转化为比赛分。
- **影响**：拿到官方计分表后，按 `新增分值 / (预计耗时 + 死亡循环风险)` 排序；冲下界/要塞必须绑定时间与死亡止损阈值——一旦超时或进入 `safe_mode`，立即回退主世界收割农牧、村民交易、附魔、铁傀儡等高确定性进度。
- **推翻条件**：赛前公布的正式计分表把跨分类主线人工定义为连续累加深度（>10 级），且删减绝大部分主世界支线 advancement。

## J13 · 模型 ID、思考开关、并发上限与预算熔断统一配置化（@de7provincien-c 2026-11-12）

- **依据**：书面公告（`DeepSeek V4.1 Flash`、8M/1.5M 额度、4 并发）、群聊口头补充（`qwen3.6-35b-a3b` 无限额度、24 并发）与队内不同方案之间存在多处模型名和配额假设差异，赛前乃至赛中均可能切换。
- **影响**：代码层严禁硬编码模型名称或写死无配额假设，统一由配置读取 `LLM_MODEL`、`LLM_ENABLE_THINKING`、`LLM_MAX_CONCURRENCY`、`LLM_TOKEN_BUDGET`（设为 `0` 时关闭硬熔断、仅记录累计 token），确保不改代码即可适配正式赛口径。
- **推翻条件**：主办方提供唯一封装死参数的本地 SDK 且不允许任何配置覆盖。

## J14 · 得分 = 难度分值之和 ⇒ 问题是"加权集合覆盖"，不是"爬树"

- **依据**：v2 草案「每项的分值只由难度等级决定」；120 项计分表中，计分项分值合计 **3385**，其中 100 分 7 项、60 分 21 项、30 分 32 项、15 分 27 项、5 分 12 项 `[RULES v2 草案]`
- **影响**：不再有"越深越值钱"，只看**难度单价 × 能不能做完**。策略从"沿一条深链走"改为"在时间预算内挑一批高单价、且共享前置的项"
- **推翻条件**：最终版规则把深度项加回来

## J15 · 岛的内容决定得分上限 ⇒ 开局先做"岛体检"

- **依据**：120 项里 **54 项**写的是「岛上有……时计分」（要塞、堡垒、村庄、试炼密室、蜂巢、丛林、繁茂洞穴、暖水废墟、山地、热带草原、三种群系…），具体取决于最终选定的岛
- **影响**：计划必须在开局 10 分钟内按实际观察重排——先扫岛（结构、群系、岩浆湖、可疑沙砾），再选目标；**不能按"应该有要塞"排死计划**
- **推翻条件**：主办方承诺所有岛都包含全部所需结构

## J16 · 虚空赛制把"坠落"变成一级风险

- **依据**：v2 草案「四周是虚空」「虚空岛底下没有地面」（计分表里 `fall_from_world_height` 正因此不计分）
- **影响**：挖矿要防挖穿、搭桥要防走空、被击退要防落空。一次坠落 = 掉出世界，比普通死亡更贵。安全层要新增"脚下无方块"检查
- **推翻条件**：岛底有基岩封底

## J17 · 校验器只能保证"结构合法"，保证不了"值是真的"

- **依据**：真机抽测里模型输出 `attack {"entity_id": 1}` —— 结构完全合法（`entity_id` 是真实参数名、是整数），
  但那个 `1` 是它**编的**：状态里只说了"附近有 zombie dist=4"，没给 id `[实测 2026-11-13]`
- **影响**：`validate()` 挡不住这类幻觉。执行层必须做二次核对——`attack`/`shoot`/`interact(entity_id)` 前
  先用 `/get_entities` 确认 id 存在且距离合理；`dig`/`move_to` 的坐标要先 `get_block`/`/status` 核对
- **推翻条件**：状态摘要里始终携带全部实体 id 与坐标，模型无需猜测

## J18 · 结构类进度只看“人站在哪” ⇒ 岛体检用方块指纹定位，Eye Spy 不需要末影之眼（@claude 2026-11-13）
