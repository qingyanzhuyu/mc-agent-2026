## 三条硬约束

1. **动作互斥 + 同步阻塞**（见 J1）。执行器必须是串行单飞锁；并发只对"想"有意义（v1.3.14 `/control wait:false` 与 v1.3.19 `/chat` 放宽了对应接口的占锁时长，但核心世界动作仍互斥）。
2. **能力边界**：无矿透、无鞘翅。`stop_on` 默认 `["hurt","death"]`，`/attack` 和 `/shoot` 默认只在死亡时中断。部分成功的响应读 `result.interrupted_by`，失败的中断读 `error.cause`（§4）。
3. **死亡代价（2026-11-22 更新）**：~~60s 死 3 次 → 下线 5 分钟~~（上游 `v1.3.17` commit `8422c53` 已移除死亡循环断开与 5 分钟冷却，改为保留会话自动重生）；但正式赛 **`keepInventory = false`**（J21），死亡仍会丢失全部随身背包与护甲，安全抢占与避难所仓库仍是最高优先级。

## 架构

```
                 ┌──────────── Planner（开思考，每 2–5 min，长上下文）
                 │   输出：任务 DAG + 当前目标 + 资源缺口
                 ▼
  events/status ─→ Tactician（关思考，每动作一次，1–3 s）
   (不占锁轮询)      输出：下一个 API 调用 + 参数（JSON）
                 ▼
                 Executor（串行单飞，带超时/重试/降级）
                 │
                 ├─ 动作期间：并行预取下一步决策（把 LLM 延迟藏进动作耗时）
                 └─ 失败码分类：RETRY / REPLAN / FATAL
                 ▲
              Safety（最高优先级，可抢占）
              hp<8 | 岩浆 | 虚空 | 敌对<6格且hp<12 | deaths_in(60)>=2 → /stop + 处置
```

## 四条工程红线

1. **只认 `ok` 字段**：业务错误也是 HTTP 200，看状态码会误判成功。
2. **一次动作一次调用**：RTT ≈ 0.6s，一个动作配 3 次观察就是 1.8s 纯开销；3000 个动作 ≈ 1.5 小时。能合并进上下文就合并，优先用 `/events` 增量。
3. **空/错响应必须当失败**：`ok:false` 要分类处理；LLM 返回空 content（思考把 token 吃光）要重试，不能当成"模型没话说"。
4. **token 过期要自动重登**：`expires_at` 存在但 TTL 未公开；重登会踢掉旧连接，需重走 `wait_ready`。

## 超时建议（实测后调）

| 动作 | HTTP 超时 |
|---|---|
| `move_to` | 180s |
| `attack` | 90s |
| `use_item` | 90s |
| `dig` | 40s |
| 其余 | 20–30s |

> 超时**必须大于**动作本身的时长，否则会把"走得远"误判成失败；失败后补一次 `/stop` 兜底。
> 运行时实现（`code/mcagent/runtime.py`）：`Executor.move_to(..., timeout=None, *, retries=2, stop_on=None)` 支持按需透传有界 `timeout`（为 `None` 时省略 `timeout` 关键字参数）；传入有界 `timeout` 时将 `requests.ReadTimeout` 导致的 `ApiError("network")` 归一为 `timeout`（由 `STOP_ON_TIMEOUT_ACTIONS` 补发 `/stop`），且 `Executor.act` 对单次尝试单调耗时 `>= 20.0s`（`_NO_RETRY_TIMEOUT_ELAPSED_S = 20.0`）的 `timeout` 抑制重试，短时或瞬时 `timeout` 仍按 `retries` 上限重试。

## 2026-11-13 · 写主循环前的四层调度基础设施

来源：队内四层调度设计与 J1/J8/J11/J13/J16。协议依据为[上游规范 v1.3.11](99-原始记录/api-spec-v1.3.11.md) §0、§3.1、§3.4、§3.6、§4、§4.1、§4.5。**验证等级：协议与并发机制 verified: offline，默认物理阈值、寻路、逃生技能及主循环仍待 verified: live。**

| 层 | 已提供的机制 | 接入约定 |
|---|---|---|
| 服务端反射 | `Client.action()` 与全部阻塞动作方法均支持显式 `stop_on`；默认 `hurt,death`，`attack`/`shoot` 为 `death` | `Client`/`Executor`/`decision.validate()` 全量透传 `stop_on`（如着火/中毒进食可传 `use_item(..., stop_on=["death"])`），不得绕过 `Executor` 裸调 |
| 后台看护 | `SafetyMonitor` 定时共享 status/events，安全 4s、风险 1s；同一持续危险只急停一次，解除后还须过冷静期 | 通常不设 `on_hazard`，由执行层消费 `state.safety_intent`；旧同步逃生回调仍兼容，但长回调会占用看护线程，不建议新代码使用 |
| 技能执行 | `State.refresh_status(client)` 在 TTL 1s 内复用，过期并发补读合并；动作仍用既有 Executor 单飞/抢占锁 | 主循环每次发动作前调 refresh_status，然后先检查 safety_intent，再推进一步；不要自己定时读 events |
| 模型决策 | `DecisionScheduler.notify/poll` 单工作线程，8s 总期限（`LLMClient.decide(total_timeout=...)` 兜底重试总耗时），过时回复丢弃，不阻塞动作；常规事件至少隔 20s，周期复盘 240s | 只收纯思考回调，如 `lambda summary: llm.decide(summary, total_timeout=8.0)[0]`；回调不能持有 Executor 或执行动作 |

`notify` 的事件为 `skill_done`、同技能连续两次 `skill_failed`、`phase_changed`、`uncovered`、到期 `review`；其中 `20s` 最小间隔仅节流常规事件（`skill_done`、`review`），阶段切换、未覆盖场景及连续失败达标只要无在途工作线程即刻触发。每次目标/安全上下文变化调用 `invalidate()`。`poll(fallback)` 没结果且未超时返回 `None`，执行层继续当前技能；到期/失败调用固定规则 fallback，返回后绝不采纳该次迟到答复。工作线程仍未结束时不再开新请求，避免积累悬挂调用。`iron_complete=False` 不调用模型。**铁器前固定技能队列及铁器后的目标选择尚未实现，本轮不提前写主循环。**

低血（≤8）、近敌（<6）和着火发布软安全意图，不中断移动；执行层在动作边界换进食/撤退技能。`attack`/`shoot` 期间低血升级急停。岩浆、缺氧、无支撑风险、死亡循环避险为急停，且危险优先级固定将 `escape_lava`、`surface`、`void_risk` 排在 65s `safe_mode` 之前，防止复活冷却掩盖致命物理危险。持续危险锁存优先于冷静期：不会每隔 N 秒再停一次；新种类危险独立触发。`/stop` 失败不记成功锁存，后续轮询重试；逃生回调失败不抹掉已成功的急停锁存。

风险加速条件：夜间、下界、16 格内敌对生物、血量<14、水中/着火/岩浆/离地，或技能通过 `state.set_risk_context(near_water=True, near_void=True, void_guard=True)` 标记的环境。接口没有“在水边/虚空边”字段，不能凭空推断；技能应依据已观察地形设置并在结束后清除这些上下文。

虚空保护用 §3.4 `get_block` 查询 `floor(x), floor(y-0.01), floor(z)`，在 `get_block` **返回后**再打单调时钟时间戳（默认 `MC_SUPPORT_TTL_S=5`，避免官方约 2s RTT 导致证据刚返回即过期）。`sneaking=True` 且 `on_ground=True`（潜行探边搭桥）及向上起跳阶段豁免误报；非潜行走过单格桥/窄边且服务端物理判定 `on_ground=True`（且未下降）时，若中心点落在相邻空气格，会按玩家 `0.6×0.6` 水平碰撞箱加 `/status` 一位小数四舍五入容差（`±0.35`）补查四角邻格是否存在实心承重块（命中记入 `aabb_support`），避免正常贴边上桥被误发 `/stop`；桥/虚空上下文下其余离地或四角全空的脚下空气立即视作无支撑风险；普通地形离地下降时额外向下探查 2 格（`under_y - 1`、`under_y - 2`），避免下 1–2 格台阶误触发 `/stop`，水中/载具内不按虚空判定。查询失败/未加载在高风险路径上也不能按安全处理。**两三格空气仍不证明下方一直是虚空；复杂非完整方块仍可能存在边界误差。**保护会保留坐标、方块/错误和观测时间，过期或位置变化的证据不会被复用；这个启发式仍须在官方环境完成 C16 标定，不能承诺已经解决 Minecraft 的全部坠落风险。

缓存带单调时钟时间戳；动作返回只更新 pos/health/food，不刷新旧 status 的整体读取时间。`State.drain()` 在进程冷启动首次拉取时自动翻页追平历史事件（最多 20 页 `has_more`），防止中途重启把第 2 页以后的陈旧 `death` 事件盖上当前时间戳误触发 65s `safe_mode`；追平后稳态每轮只读 1 页。背包按脏标记懒刷新：`dig`、`craft`、`window/act`、消耗/装备/掉落等写动作结束（包括异常）以及 `pickup`/`death` 事件使其失效（只读 `window/view` 不失效）；非幂等动作仅对 `SNAPSHOT_INVENTORY_ACTIONS`（`craft`、`window/act`、`use_item`）做动作前背包补读判重，连续 `place` 搭桥不会每块触发额外 `GET /inventory`。普通状态缓存命中无需额外 status 请求；**“每动作额外≤1”是待测目标，不是硬保证**，背包首次读取/失效、异常恢复与支撑检查可能超出，需要 C1/真实动作流量验证。

`.env.example` 包含全部本轮新增频率/阈值；程序应先 `Config.load()` 再创建 State/Scheduler，以加载 `.env`。`MC_MAX_RPS` 最初曾设上限为 4；2026-11-18 经人类批准放宽为默认且最高 `16`（依据 `api-spec-v1.3.11.md` §0/§3 观察接口不占动作锁可与动作并发），`RequestLimiter` 采用三级优先调度（`/stop` 急停 > 主线程动作/查方块 > `Client.background_observation()` 后台连续观察，防止后台轮询挤占主线程）。注意 `16 RPS` 仍为客户端本地/校园网护栏上限，**不是主办方对“恶意请求”的安全认定**；公网隧道场景受 RTT 自然限制，比赛服仍需结合实际防洪约束评估。此外 `Client.get_block(pos, use_cache=True)` 默认提供 `MC_BLOCK_CACHE_TTL_S=1.5` 秒只读缓存并在写动作/连接变更时自动失效（`SafetyMonitor._check_support` 显式 `use_cache=False` 绕过缓存）；`SafetyMonitor(continuous=True)` 支持每次 `tick()` 返回后连续异步刷新 `status` / `events` / 脏 `inventory`，按风险自适应退避：危险/离地态按 `MC_OBSERVER_MIN_INTERVAL_S=0.25` 紧凑续刷，干燥接地安全态退避至 `min(MC_POLL_RISK_S, 3×MC_OBSERVER_MIN_INTERVAL_S)`（默认 `0.75s < MC_STATUS_TTL_S=1.0s`），兼顾 LLM 快照命中率与防 `/status` 刷爆；`MainLoop` 启用监控器时默认直接复用最新后台观察快照供模型决策而不阻塞等待。

### 寻路 probe 的运行方式与证据标准

新模式保留旧 probe 的结果结构；旧模式动作也已接入 Executor 并统一捕获 `Replan`/`Fatal` 正常落盘，去掉强制 login，自动复用 token。新模式默认不联网：

```bash
cd code
uv run python -m mcagent.probe --pathfinding --dry > /tmp/path-fixture.json
# 也可在已获准的测试场只读采样当前位置与周边方块草稿（不移动、不改世界）：
uv run python -m mcagent.probe --pathfinding --snapshot > /tmp/path-snapshot.json
# 在赛前获准的官方测试场，核对并补齐模板中的 start/target/witness_blocks。
uv run python -m mcagent.probe --pathfinding --fixture /tmp/path-fixture.json --case wall --dry
# 人类已授权账号登录、docs/05 已占位后再执行（本轮未执行）：
uv run python -m mcagent.probe --pathfinding --fixture /tmp/path-fixture.json --case wall --live
```

可选 case：`move20`、`dig1`、`wall`、`gap`、`pillar`、`climb_y`、`climb_xz`、`water`、`manual_breach`、`manual_bridge`、`manual_step_up`、`pearl`；不传 `--case` 则默认按此顺序跑全部（先跑零伤无损的 C1 基线，再跑裸 `move_to` 能力探测与三项手动兜底序列，最后跑有落点伤害的珍珠），也可传 `--manual-only` 仅跑 `climb_xz` 与三项手动兜底序列（`manual_breach`：`equip` 最优镐 + 逐格挖 `1×2` 通道 + `move_to`；`manual_bridge`：`posture(sneak=True)` + 侧面连摆桥面 + 复位潜行过桥；`manual_step_up`：先验证脚下自放 `blocked_by_self`，再以 `1×2` 双列交替垫块 + 潜行迈步原地拔高），仅在 `Fatal`、角色死亡或 `urgent` 级紧急危险未解除时中止后续 case。可重复 `--case` 选择子集。`gap`/`pillar`/`manual_bridge`/`manual_step_up` 默认不强开 `void_guard`（以免跳跃腾空被看护线程误杀），如需顺带标定虚空探针可显式加 `--void-guard`。`--samples` 控制 T_status 采样（默认5）；`--pearl-trials` 控制珍珠试投（默认3，要求对应数量物品且每次投掷前 `health > 6`），报告 3D/水平/垂直误差与 3D p50/max。`--output` 指定原始证据文件；默认在已忽略的 `mcagent/probe/pathfinding-*.json`，每个 case 开始和结束都会原子落盘，异常也保存已获证据，最终 stop/disconnect。

准备路径和被测路径均经 Executor，单次测试不自动重试动作。石墙/坑/搭柱/水及手动开路/搭桥/垫高序列的 witness_blocks 必填，留前后方块、背包、状态轨迹、事件、手动子步骤（`manual_steps`）原始结果与耗时。能力探测与手动序列若服务端直接返回业务拒绝（`path_not_found`/`timeout`/`out_of_reach`/`blocked_by_self`/`no_support_block`），记为 `status="observed"`（`outcome="rejected:<code>"`）并继续后续 case；仅当发生真实抢占急停（`_preempt_epoch` 递增）或 `urgent` 危险时标 `safety_interference=true`、`status="inconclusive"`（珍珠连投后 `health <= 8` 的软 `heal` 意图不污染已完成的落点样本）。石墙要观察是否破坏挡路石块，不能把绕行成功当作会挖墙；坑/柱/手动搭桥/双列垫高必须用**有安全底板的测试场**，不要在真实虚空上试能力。带 `y`（`climb_y`）、不带 `y` 仅传 `(x, z)`（`climb_xz`）爬现成台阶与原地搭柱分别测试。珍珠仅 `teleported=true` 的试验纳入误差统计，目标是瞄准点，误差不是已证明的瞄准精度承诺。

C1：T_status 在每次采样前先等客户端限速槽就绪再起表，测量真实单次 HTTP RTT（避免把 `1/MC_MAX_RPS` 的客户端节流睡眠混入 RTT），保存每次及中位数；move20 要求夹具起终点水平距离 20，默认 `range=1` 并按整数方块坐标与实体脚底中心（`+0.5`）的水平容差（`max(1.8, range + 0.8)`）判定就位与到达；dig1 要求单块 stone 且禁止脚下承重块（夹具 `start` 建议距目标水平 ≥2 格防 `GoalNear` 停在目标正上方）。动作计时包含完整客户端调用开销，成功且未受安全干扰才填 T_move20/T_dig1，失败保留错误而不冒充耗时基线。先单项确认夹具，再运行全套。正式数值仍留空。

默认只认官方主机名（`preflight.OFFICIAL_HOSTS`：`apiin.nmo.net.cn` 与 `mc-api.windywindie.top`）；非官方地址必须显式 `--local-target`，报告 source 永远记为 local-target，不得纳入官方能力或预算。手填夹具是**赛前测试工具**，不能用于赛中人工探图并硬编码当场坐标（AGENTS §2B）。

此外，`uv run python -m mcagent.probe --api-capabilities --dry` 提供部署能力探针的离线计划预览；获授权并在 `docs/05` 占位后改传 `--live`，对空闲 bot 发送无按键 `/control`（预期 `bad_args` 表示路由存在，`unsupported_api` 表示旧部署无此路由）、按当前角度调用 `/look`，并检查空闲 `/stop` 是否返回 `released` 字段，用于 B18 无损取证。
