# 02 · 接口与架构

> 依据规范 v1.3.1（原文见 `99-原始记录/api-spec-v1.3.1.md`）。
> 端点实测：`GET /status` 未授权返回 `{"ok":false,"error":{"code":"unauthorized"}}`，RTT ≈ 0.6s（直连）。

## 能力地图（按"能干什么"组织）

### 观察层（**不占动作锁**，动作进行中也能读）

| 能力 | 接口 | 关键点 |
|---|---|---|
| 自身状态 | `GET /status` | `ready` / `busy` / `nearest_hostile` / `last_death` / `armor_points` / `xp_progress` |
| 背包 | `GET /inventory` | 附魔、自定义名、药水、`empty_slots` |
| 找方块 | `POST /find_blocks` | radius ≤ **64**；**只返回暴露方块**；支持属性筛选、摘要模式 |
| 单方块 | `POST /get_block` | `diggable` / `hardness` / `harvest_tool_ok` / `mature` |
| 实体 | `POST /get_entities` | radius 32，最多 40 个，类别或具名 |
| 事件流 | `GET|POST /events` | **`seq` 自增**；返回最早 N 条 + `has_more`；limit ≤ 500 |
| 进度 | `POST /advancements` | 可见进度树 + `completed_at` + `progress` |

### 动作层（**互斥、阻塞**）

| 类别 | 接口 | 说明 |
|---|---|---|
| 移动 | `/move_to` | 自动寻路；骑乘时自动切掌舵（船 8 / 马 9 格/秒，不绕障） |
| 挖 / 放 | `/dig` `/place` | `place` 自动潜行，可直接在容器/床/工作台上放 |
| 交互 | `/interact` | 方块（门/拉杆/床/种子）或实体（喂食/驯服/剪毛/挤奶/上下载具） |
| 用物品 | `/use_item` | 按类别分派并等效果结束：吃/喝/盾/末影珍珠/**末影之眼(给 bearing_deg)**/钓鱼/望远镜 |
| 近战 | `/attack` | **追到死或超时；自动换武器、自动捡掉落** |
| 远程 | `/shoot` | 弓/弩/三叉戟；**算弹道 + 对移动目标提前量**，返回 `predicted_miss` |
| 合成 | `/craft` | 2×2 免工作台；失败附 `example_recipe_needs` |
| 界面 | `/window/view` `/window/act` | 箱子/熔炉/工作台/附魔台/铁砧/砂轮/锻造台/切石机/织布机/酿造台/信标/村民 |
| 其他 | `/equip` `/posture` `/drop` `/chat` `/stop` `/dismount` | `posture` 不占锁，可在 `move_to` 中途调 |

## 三条硬约束

1. **动作互斥 + 同步阻塞**（见 J1）。执行器必须是串行单飞锁；并发只对"想"有意义。
2. **能力天花板**：无矿透 / 无鞘翅 / 无逐 tick；`stop_on` 默认 `["hurt","death"]`（走路易被打断），`/attack` 默认只中断于 `death`（**攻击中被打死不会自动停**，安全层须主动 `/stop`）。
3. **死亡循环**：60s 死 3 次 → 下线 5 分钟。这是唯一的一票否决。

## 架构

```
                 ┌──────────── Planner（开思考，每 2–5 min，长上下文）
                 │   输出：任务 DAG + 当前目标 + 资源缺口
                 ▼
  events/status ─→ Tactician（关思考，每动作一次，1–3 s）
   (不占锁轮询)      输出：下一个 API 调用 + 参数（JSON）
                 ▼
                 Executor（串行单飞，带超时/重试/降级）
                 │
                 ├─ 动作期间：并行预取下一步决策（把 LLM 延迟藏进动作耗时）
                 └─ 失败码分类：RETRY / REPLAN / FATAL
                 ▲
              Safety（最高优先级，可抢占）
              hp<8 | 岩浆 | 虚空 | 敌对<6格且hp<12 | deaths_in(60)>=2 → /stop + 处置
```

## 四条工程红线

1. **只认 `ok` 字段**：业务错误也是 HTTP 200，看状态码会误判成功。
2. **一次动作一次调用**：RTT ≈ 0.6s，一个动作配 3 次观察就是 1.8s 纯开销；3000 个动作 ≈ 1.5 小时。能合并进上下文就合并，优先用 `/events` 增量。
3. **空/错响应必须当失败**：`ok:false` 要分类处理；LLM 返回空 content（思考把 token 吃光）要重试，不能当成"模型没话说"。
4. **token 过期要自动重登**：`expires_at` 存在但 TTL 未公开；重登会踢掉旧连接，需重走 `wait_ready`。

## 超时建议（实测后调）

| 动作 | HTTP 超时 |
|---|---|
| `move_to` | 180s |
| `attack` | 90s |
| `use_item` | 90s |
| `dig` | 40s |
| 其余 | 20–30s |

> 超时**必须大于**动作本身的时长，否则会把"走得远"误判成失败；失败后补一次 `/stop` 兜底。
