# 02 · 接口与架构

> 依据规范 v1.3.1（原文见 `99-原始记录/api-spec-v1.3.1.md`）。
> 端点实测：`GET /status` 未授权返回 `{"ok":false,"error":{"code":"unauthorized"}}`，RTT ≈ 0.6s（直连）。

## 能力地图（按"能干什么"组织）

### 观察层（**不占动作锁**，动作进行中也能读）

| 能力 | 接口 | 关键点 |
|---|---|---|
| 自身状态 | `GET /status` | `ready` / `busy` / `nearest_hostile` / `last_death` / `armor_points` / `xp_progress` |
| 背包 | `GET /inventory` | 附魔、自定义名、药水、`empty_slots` |
| 找方块 | `POST /find_blocks` | radius ≤ **64**；**只返回暴露方块**；支持属性筛选、摘要模式 |
| 单方块 | `POST /get_block` | `diggable` / `hardness` / `harvest_tool_ok` / `mature` |
| 实体 | `POST /get_entities` | radius 32，最多 40 个，类别或具名 |
| 事件流 | `GET|POST /events` | **`seq` 自增**；返回最早 N 条 + `has_more`；limit ≤ 500 |
| 进度 | `POST /advancements` | 可见进度树 + `completed_at` + `progress` |

### 动作层（**互斥、阻塞**）

| 类别 | 接口 | 说明 |
|---|---|---|
| 移动 | `/move_to` | 自动寻路；骑乘时自动切掌舵（船 8 / 马 9 格/秒，不绕障） |
| 挖 / 放 | `/dig` `/place` | `place` 自动潜行，可直接在容器/床/工作台上放 |
| 交互 | `/interact` | 方块（门/拉杆/床/种子）或实体（喂食/驯服/剪毛/挤奶/上下载具） |
| 用物品 | `/use_item` | 按类别分派并等效果结束：吃/喝/盾/末影珍珠/**末影之眼(给 bearing_deg)**/钓鱼/望远镜 |
| 近战 | `/attack` | **追到死或超时；自动换武器、自动捡掉落** |
| 远程 | `/shoot` | 弓/弩/三叉戟；**算弹道 + 对移动目标提前量**，返回 `predicted_miss` |
| 合成 | `/craft` | 2×2 免工作台；失败附 `example_recipe_needs` |
| 界面 | `/window/view` `/window/act` | 箱子/熔炉/工作台/附魔台/铁砧/砂轮/锻造台/切石机/织布机/酿造台/信标/村民 |
| 其他 | `/equip` `/posture` `/drop` `/chat` `/stop` `/dismount` | `posture` 不占锁，可在 `move_to` 中途调 |

## 三条硬约束

1. **动作互斥 + 同步阻塞**（见 J1）。执行器必须是串行单飞锁；并发只对"想"有意义。
2. **能力天花板**：无矿透 / 无鞘翅 / 无逐 tick；`stop_on` 默认 `["hurt","death"]`（走路易被打断），`/attack` 默认只中断于 `death`（**攻击中被打死不会自动停**，安全层须主动 `/stop`）。
3. **死亡循环**：60s 死 3 次 → 下线 5 分钟。这是唯一的一票否决。

## 架构

```
                 ┌──────────── Planner（开思考，每 2–5 min，长上下文）
                 │   输出：任务 DAG + 当前目标 + 资源缺口
                 ▼
  events/status ─→ Tactician（关思考，每动作一次，1–3 s）
   (不占锁轮询)      输出：下一个 API 调用 + 参数（JSON）
                 ▼
                 Executor（串行单飞，带超时/重试/降级）
                 │
                 ├─ 动作期间：并行预取下一步决策（把 LLM 延迟藏进动作耗时）
                 └─ 失败码分类：RETRY / REPLAN / FATAL
                 ▲
              Safety（最高优先级，可抢占）
              hp<8 | 岩浆 | 虚空 | 敌对<6格且hp<12 | deaths_in(60)>=2 → /stop + 处置
```

## 四条工程红线

1. **只认 `ok` 字段**：业务错误也是 HTTP 200，看状态码会误判成功。
2. **一次动作一次调用**：RTT ≈ 0.6s，一个动作配 3 次观察就是 1.8s 纯开销；3000 个动作 ≈ 1.5 小时。能合并进上下文就合并，优先用 `/events` 增量。
3. **空/错响应必须当失败**：`ok:false` 要分类处理；LLM 返回空 content（思考把 token 吃光）要重试，不能当成"模型没话说"。
4. **token 过期要自动重登**：`expires_at` 存在但 TTL 未公开；重登会踢掉旧连接，需重走 `wait_ready`。

## 超时建议（实测后调）

| 动作 | HTTP 超时 |
|---|---|
| `move_to` | 180s |
| `attack` | 90s |
| `use_item` | 90s |
| `dig` | 40s |
| 其余 | 20–30s |

> 超时**必须大于**动作本身的时长，否则会把"走得远"误判成失败；失败后补一次 `/stop` 兜底。

## 2026-11-13 · 写主循环前的四层调度基础设施

来源：用户本轮设计要求；协议依据为 `docs/99-原始记录/api-spec-v1.3.1.md` §0、§3.1、§3.4、§3.6、§4、§4.1、§4.5；判断依据 J1/J8/J11/J13/J16。此节补充并更新旧版“每轮危险都 emergency”的调用方式。**验证等级：协议/并发机制 verified: offline；默认物理阈值、寻路、逃生技能、主循环仍待 verified: live。**

| 层 | 已提供的机制 | 接入约定 |
|---|---|---|
| 服务端反射 | `Client.action()` 与全部阻塞动作方法均支持显式 `stop_on`；默认 `hurt,death`，`attack`/`shoot` 为 `death` | `Client`/`Executor`/`decision.validate()` 全量透传 `stop_on`（如着火/中毒进食可传 `use_item(..., stop_on=["death"])`），不得绕过 `Executor` 裸调 |
| 后台看护 | `SafetyMonitor` 定时共享 status/events，安全 4s、风险 1s；同一持续危险只急停一次，解除后还须过冷静期 | 通常不设 `on_hazard`，由执行层消费 `state.safety_intent`；旧同步逃生回调仍兼容，但长回调会占用看护线程，不建议新代码使用 |
| 技能执行 | `State.refresh_status(client)` 在 TTL 1s 内复用，过期并发补读合并；动作仍用既有 Executor 单飞/抢占锁 | 主循环每次发动作前调 refresh_status，然后先检查 safety_intent，再推进一步；不要自己定时读 events |
| 模型决策 | `DecisionScheduler.notify/poll` 单工作线程，8s 总期限（`LLMClient.decide(total_timeout=...)` 兜底重试总耗时），过时回复丢弃，不阻塞动作；常规事件至少隔 20s，周期复盘 240s | 只收纯思考回调，如 `lambda summary: llm.decide(summary, total_timeout=8.0)[0]`；回调不能持有 Executor 或执行动作 |

`notify` 的事件为 `skill_done`、同技能连续两次 `skill_failed`、`phase_changed`、`uncovered`、到期 `review`；其中 `20s` 最小间隔仅节流常规事件（`skill_done`、`review`），阶段切换、未覆盖场景及连续失败达标只要无在途工作线程即刻触发。每次目标/安全上下文变化调用 `invalidate()`。`poll(fallback)` 没结果且未超时返回 `None`，执行层继续当前技能；到期/失败调用固定规则 fallback，返回后绝不采纳该次迟到答复。工作线程仍未结束时不再开新请求，避免积累悬挂调用。`iron_complete=False` 不调用模型。**铁器前固定技能队列及铁器后的目标选择尚未实现，本轮不提前写主循环。**

低血（≤8）、近敌（<6）和着火发布软安全意图，不中断移动；执行层在动作边界换进食/撤退技能。`attack`/`shoot` 期间低血升级急停。岩浆、缺氧、无支撑风险、死亡循环避险为急停，且危险优先级固定将 `escape_lava`、`surface`、`void_risk` 排在 65s `safe_mode` 之前，防止复活冷却掩盖致命物理危险。持续危险锁存优先于冷静期：不会每隔 N 秒再停一次；新种类危险独立触发。`/stop` 失败不记成功锁存，后续轮询重试；逃生回调失败不抹掉已成功的急停锁存。

风险加速条件：夜间、下界、16 格内敌对生物、血量<14、水中/着火/岩浆/离地，或技能通过 `state.set_risk_context(near_water=True, near_void=True, void_guard=True)` 标记的环境。接口没有“在水边/虚空边”字段，不能凭空推断；技能应依据已观察地形设置并在结束后清除这些上下文。

虚空保护用 §3.4 `get_block` 查询 `floor(x), floor(y-0.01), floor(z)`，在 `get_block` **返回后**再打单调时钟时间戳（默认 `MC_SUPPORT_TTL_S=5`，避免官方约 2s RTT 导致证据刚返回即过期）。`sneaking=True` 且 `on_ground=True`（潜行探边搭桥）及向上起跳阶段豁免误报；桥/虚空上下文下其余脚下空气立即视作无支撑风险；普通地形离地下降时额外向下探查 2 格（`under_y - 1`、`under_y - 2`），避免下 1–2 格台阶误触发 `/stop`，水中/载具内不按虚空判定。查询失败/未加载在高风险路径上也不能按安全处理。**两三格空气仍不证明下方一直是虚空；返回字段没有碰撞箱，复杂地形仍可能误报。**保护会保留坐标、方块/错误和观测时间，过期或位置变化的证据不会被复用；这个启发式必须在 C16 标定，不能承诺已经解决 Minecraft 的全部坠落风险。

缓存带单调时钟时间戳；动作返回只更新 pos/health/food，不刷新旧 status 的整体读取时间。`State.drain()` 在进程冷启动首次拉取时自动翻页追平历史事件（最多 20 页 `has_more`），防止中途重启把第 2 页以后的陈旧 `death` 事件盖上当前时间戳误触发 65s `safe_mode`；追平后稳态每轮只读 1 页。背包按脏标记懒刷新：`dig`、`craft`、`window/act`、消耗/装备/掉落等写动作结束（包括异常）以及 `pickup`/`death` 事件使其失效（只读 `window/view` 不失效）；非幂等动作仅对 `SNAPSHOT_INVENTORY_ACTIONS`（`craft`、`window/act`、`use_item`）做动作前背包补读判重，连续 `place` 搭桥不会每块触发额外 `GET /inventory`。普通状态缓存命中无需额外 status 请求；**“每动作额外≤1”是待测目标，不是硬保证**，背包首次读取/失效、异常恢复与支撑检查可能超出，需要 C1/真实动作流量验证。

`.env.example` 包含全部本轮新增频率/阈值；程序应先 `Config.load()` 再创建 State/Scheduler，以加载 `.env`。`MC_MAX_RPS` 默认且最多 4，所有 MC 请求（含认证、补读、重试、stop）经过同一 Client 限速器，/stop 优先取下一个槽，不突破上限。4 RPS 是队内工程上限，**不是主办方对“恶意请求”的安全认定**。在 0.6s RTT 假设下安全时 status+events 约 0.5 RPS，高风险约 2 RPS；支撑检查和动作会增加总量，由限速器兜底。慢请求不追赶补发，实际周期可能高于配置。

### 寻路 probe 的运行方式与证据标准

新模式保留旧 probe 的结果结构；旧模式动作也已接入 Executor 并统一捕获 `Replan`/`Fatal` 正常落盘，去掉强制 login，自动复用 token。新模式默认不联网：

```bash
cd code
uv run python -m mcagent.probe --pathfinding --dry > /tmp/path-fixture.json
# 也可在已获准的测试场只读采样当前位置与周边方块草稿（不移动、不改世界）：
uv run python -m mcagent.probe --pathfinding --snapshot > /tmp/path-snapshot.json
# 在赛前获准的官方测试场，核对并补齐模板中的 start/target/witness_blocks。
uv run python -m mcagent.probe --pathfinding --fixture /tmp/path-fixture.json --case wall --dry
# 人类已授权账号登录、docs/05 已占位后再执行（本轮未执行）：
uv run python -m mcagent.probe --pathfinding --fixture /tmp/path-fixture.json --case wall --live
```

可选 case：`move20`、`dig1`、`wall`、`gap`、`pillar`、`climb_y`、`water`、`pearl`；不传 `--case` 则默认按此顺序跑全部（先跑零伤无损的 C1 基线，再跑能力探测），仅在 `Fatal`、角色死亡或 `urgent` 级紧急危险未解除时中止后续 case。可重复 `--case` 选择子集。`gap`/`pillar` 默认不强开 `void_guard`（以免跳跃腾空被看护线程误杀），如需顺带标定虚空探针可显式加 `--void-guard`。`--samples` 控制 T_status 采样（默认5）；`--pearl-trials` 控制珍珠试投（默认3，要求对应数量物品且每次投掷前 `health > 6`），报告 3D/水平/垂直误差与 3D p50/max。`--output` 指定原始证据文件；默认在已忽略的 `mcagent/probe/pathfinding-*.json`，每个 case 开始和结束都会原子落盘，异常也保存已获证据，最终 stop/disconnect。

准备路径和被测路径均经 Executor，单次测试不自动重试动作。石墙/坑/搭柱/水的 witness_blocks 必填，留前后方块、背包、状态轨迹、事件、动作原始结果与耗时。能力探测（`wall`/`gap`/`pillar`/`climb_y`/`water`）若服务端直接返回寻路业务拒绝（`path_not_found`/`timeout`/`out_of_reach`），记为 `status="observed"`（`outcome="rejected:<code>"`）并继续后续 case；仅当发生真实抢占急停（`_preempt_epoch` 递增）或 `urgent` 危险时标 `safety_interference=true`、`status="inconclusive"`（珍珠连投后 `health <= 8` 的软 `heal` 意图不污染已完成的落点样本）。石墙要观察是否破坏挡路石块，不能把绕行成功当作会挖墙；坑/柱必须用**有安全底板的测试场**，不要在真实虚空上试能力。带 y 爬现成台阶与原地搭柱分别测试。珍珠仅 `teleported=true` 的试验纳入误差统计，目标是瞄准点，误差不是已证明的瞄准精度承诺。

C1：T_status 在每次采样前先等客户端限速槽就绪再起表，测量真实单次 HTTP RTT（避免把 `1/MC_MAX_RPS` 的客户端节流睡眠混入 RTT），保存每次及中位数；move20 要求夹具起终点水平距离 20，默认 `range=1` 并按整数方块坐标与实体脚底中心（`+0.5`）的水平容差（`max(1.8, range + 0.8)`）判定就位与到达；dig1 要求单块 stone 且禁止脚下承重块（夹具 `start` 建议距目标水平 ≥2 格防 `GoalNear` 停在目标正上方）。动作计时包含完整客户端调用开销，成功且未受安全干扰才填 T_move20/T_dig1，失败保留错误而不冒充耗时基线。先单项确认夹具，再运行全套。正式数值仍留空。

默认只认固定官方 base；非官方地址必须显式 `--local-target`，报告 source 永远记为 local-target，不得纳入官方能力或预算。手填夹具是**赛前测试工具**，不能用于赛中人工探图并硬编码当场坐标（AGENTS §2B）。
