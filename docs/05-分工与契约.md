## 3. 模块契约（**冻结面**，改这里要先跟人类说）

并行开发能成立，靠的是这几个签名不变。新增方法随便加，**已有方法的返回结构不许改**。

### `client.Client` — 抛 `ApiError`，返回 `result` 字典

```python
# 认证 / 连接（自动持久化复用 .token.json，401 单点刷新）
login() -> None                                    # 强制登录并原子写盘 .token.json
ensure_connected(min_interval_s=31.0) -> dict      # 遵守规范 §2.1 ≥30s 间隔重连游戏服
wait_ready(timeout=120) -> dict                    # 轮询到 ready=True（大厅未连接自动 connect），返回 status
probe() -> str                                     # 不带 token 打 /status，返回错误码（用于 --dry）
connect() -> dict ; disconnect() -> dict ; stop() -> dict

# 观察（不占动作锁）
status() -> dict
inventory() -> dict
find_blocks(types=None, radius=16, limit=20, properties=None, mature=None) -> dict
get_block(pos) -> dict
get_entities(radius=32, types=None) -> dict
events(since=0, limit=100) -> dict
advancements(status="completed", include_recipes=False) -> dict

# 动作（互斥、阻塞）
move_to(x=None, z=None, y=None, entity_id=None, rng=1, pos=None) -> dict
dig(pos, collect=True) -> dict
place(item, pos=None) -> dict
interact(pos=None, entity_id=None, item=None) -> dict
use_item(item, target=None, ms=None, timeout_ms=None, source=None) -> dict
attack(entity_id, timeout_ms=20000) -> dict
shoot(entity_id=None, pos=None, weapon="bow", charge_ms=1100) -> dict
craft(item, count=1) -> dict
window_view(target) -> dict ; window_act(target, ops) -> dict
equip(item, slot="hand") -> dict                   # 兼容 chest->torso, offhand->off-hand
posture(sneak=None, shield=None) -> dict           # 单传一方时自动合并另一方当前状态；无参全清零
dismount() -> dict ; drop(item, count=1) -> dict ; chat(message) -> dict  # chat 自动转义前导 '/'
```

### `runtime` — 上层依赖这三个核心类（及可选 `SafetyMonitor`）

```python
State:   .st .last_seq .inventory .pos .hp .ready .in_safe_mode .safe_mode_remaining
         set_status(dict) / set_inventory(dict) / drain(client) -> list[dict]
         count(item) -> int / deaths_in(window_s=60) -> int / enter_safe_mode(cooldown_s=65.0)
         summary() -> str

Safety:  check(state) -> dict | None      # None = 安全；否则 {"kind","why"}

Executor: .n_actions .n_errors
          act(name, fn, retries=2, *, idempotent=None, verify_done=None) -> dict  # 抛 Replan / Fatal
          emergency(reason, escape_fn=None) -> Any   # 立即发 /stop 中断阻塞动作并最高优先级插队逃生
          move_to/dig/place/interact/use_item/attack/shoot/craft/window_view/window_act/
          equip/posture/dismount/drop/chat(...) / stop()

SafetyMonitor: start() / close()          # 可选后台守护线程：轮询 status+events，遇险自动调 emergency()
```

**约定**：`Executor` 内部已经做了可抢占单飞锁、非幂等动作超时判重、错误分类、重试与 JSONL 打点。上层**不要自己写重试循环**，也不要绕过 `Executor` 直接调 `client` 的动作方法——那样会没有日志、没有判重、还可能破坏抢占与互斥。

## 4. 目录归属

```
code/
  mcagent/
    client.py     接口负责人    ← 冻结面
    runtime.py    接口负责人    ← 冻结面
    smoke.py      （共用）
    probe.py      （共用，加功能可以，改输出结构要先说）
    planner/      策略负责人    ← 已建：decision.py（冻结面，单测覆盖）
    skills/       策略负责人    ← 已建：base.py（冻结面）+ 空注册表
  tests/          接口/策略共用 ← 离线故障注入与契约单测（14 用例）
tools/
  local-api-bridge/ 接口负责人  ← 赛前本地/局域网 v1.3.1 契约模拟网关（与 code/mcagent 物理隔离、零依赖）
```

新建模块请遵循：`planner/` 里只做"给什么状态 → 出什么 JSON 决策"；`skills/` 里只做"一个目标 → 一串 Executor 调用"。**skills 里不许出现 HTTP，planner 里不许出现 Executor 调用。**

### `planner` / `skills` 的冻结面

```python
planner.decision.Decision(goal, action, args, why, expect, abort_if)
planner.decision.ALLOWED_ACTIONS: tuple[str, ...]      # 16 个动作名
planner.decision.validate(obj) -> (ok, errors)
planner.decision.from_dict(obj) -> Decision            # 不合法抛 ValueError
planner.decision.bind(client, d) -> Callable[[], dict]

skills.base.Skill:  name / goal / cooldown_s / can_start(state) / step(ex, state) -> bool
skills.REGISTRY: dict[str, type[Skill]]
```

**`validate()` 用 `inspect.signature` 反射 `Client`**，所以客户端加方法后校验器自动跟上——不要改成手写白名单，那必然漂移。
