### 4.3 根因链（代码级）

1. **致命的那次 `blocked_by_self` 不是"自脚底试探"**。
   `code/mcagent/probe_path.py:40-51`（094866f 时在 `code/mcagent/probe.py:349-358`）先对自身脚底 place，
   并 `except (ApiError, Replan)` 吞掉，只记录 `self_feet_place`；它**不会**影响 `outcome`。
   真正未捕获的是第 3 块 witness 的 `place [0,65,0]`，它被 `code/mcagent/probe_path.py` 外层的
   `except (ApiError, Replan)` 记成 `outcome = rejected:<code>`。
2. **为什么第 3 块会落到自己脚下**：`Executor.act()` 只要动作结果里含 `pos` 就调用 `patch_action()`：
   `code/mcagent/runtime.py:653-654`。
   而 `place` 的 `result.pos` 是**被放置方块的坐标**（接口规范：`docs/99-原始记录/api-spec-v1.3.1.md:394`
   `{"placed":"cobblestone","pos":[100,65,-200],"sneaked":true}`），`patch_action()` 却把它当成玩家坐标写进状态缓存：
   `code/mcagent/runtime.py:194-199`。
   离线夹具 `code/tests/test_safety_layers.py:687-694` 与 `code/mcagent/skills/testing.py:71-79`（`GridWorld.place`）
   都按真实接口返回 `{"placed", "pos"}`，**夹具没有错**。
3. **错误坐标为什么会被用上**：手动序列用 `refresh_status(max_age_s=0)` 取当前位置：
   `code/mcagent/probe_path.py:42`、`code/mcagent/skills/nav.py:34-38`（`_fresh_pos`）。
   但 `code/mcagent/runtime.py:201-207` 的缓存判据是 `time.monotonic() - status_at <= ttl`；
   `ttl = 0` 时，在 15.625ms 粗时钟下会命中"同拍缓存"（实测 `delta=0.0`），拿到的是上一步 `place` 污染后的坐标。
4. **后果**：`code/mcagent/skills/nav.py:82-101` 每轮用污染坐标算"待放格是否与自己重叠"；
   第 3 块 `[0,65,0]` 被误判为重叠 → 先 `step_up_to [0.5,65,0.5]`，此时 `floor(位置)=[0,65,0]`，
   再去放 `[0,65,0]` 正好落在自己脚底 → 服务端拒绝 → 整个 case `rejected`、后续 `move_to` 不执行。
