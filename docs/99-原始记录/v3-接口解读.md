## 一、先说结论

这份规范把 v2 里悬着的 Q5–Q8 全答了，而且答得相当细（错误码、事件流、界面表都有）。但它同时暴露了三条**会改架构**的硬约束：

1. **动作互斥**：同一 bot 同一时刻只能跑一个动作，重复调用返回 `busy`。而且动作是**同步阻塞**的——`move_to` 走完才返回，`dig` 挖完才返回，`attack` 追到目标死亡或超时才返回。
   → **24 路并发只能用来"想"，不能用来"做"。** 执行的吞吐上限是"一个动作接一个动作"，跟你有多少并发无关。
2. **只返回暴露方块、无矿透、无逐 tick 键位、无鞘翅**：能力上限被钉死了。
   → 挖矿类 advancement 的边际成本极高，而战斗类几乎免费（`/attack` 自动跟打、自动换武器、自动捡掉落）。
3. **死亡循环保护：60 秒内死 3 次 → 自动下线 5 分钟。**
   → 这是全场唯一能"一票否决"你的机制。8 小时里触发两次就是 10 分钟 + 状态全丢。

## 二、能力地图（按"能干什么"组织，不是按端点罗列）

**Base**：`https://mc-api.windywindie.top/api/v1`（Cloudflare Tunnel，第三方域名，单点）· Bearer Token · 业务错误一律 HTTP 200，看 `ok`
**实测**：端点在线，未授权返回 `{"ok":false,"error":{"code":"unauthorized"}}`，RTT ≈ **0.5 s/次**

### 观察层（不占动作锁，可与动作并发）

| 能力 | 接口 | 关键点 |
|---|---|---|
| 自身状态 | `GET /status` | 47 个字段；含 `ready`、`busy`、`nearest_hostile`、`last_death`、`xp_progress`、`armor_points` |
| 背包 | `GET /inventory` | 含附魔/自定义名/药水/旗帜；`empty_slots` |
| 找方块 | `POST /find_blocks` | radius ≤ **64**；**只返回暴露方块（无矿透）**；支持属性筛选（`{"lit":true}`、`mature:true`）和摘要模式 |
| 单方块 | `POST /get_block` | 带 `diggable`/`hardness`/`harvest_tool_ok`/`mature`/`growth` |
| 实体 | `POST /get_entities` | radius 32 默认；最多 40 个；类别或具名；掉落物带 `item` |
| 事件流 | `GET|POST /events` | **`seq` 自增**，用 `last_seq` 当 `since`；返回**最早**的 N 条 + `has_more`；limit ≤ 500 |
| 进度 | `POST /advancements` | 可见进度树 + `completed_at` + `progress`（能看到 3/5 这种中间态） |

### 动作层（互斥，一次一个）

| 类别 | 接口 | 说明 |
|---|---|---|
| 移动 | `/move_to` | 自动寻路；省略 `y` 只到水平坐标；**骑乘时自动切掌舵**（船 8 / 炽足兽 4 / 猪 5 / 马 9 格/秒，不绕障） |
| 挖掘 | `/dig` | 返回 `dig_ms`、`gained`；无合适工具给 `warning` |
| 放置 | `/place` | **自动潜行**，可直接在箱子/工作台/熔炉/床上放 |
| 交互 | `/interact` | 方块（门/拉杆/按钮/床/喂种子）或实体（喂食/驯服/剪毛/挤奶/上船） |
| 用物品 | `/use_item` | 按类别分派并**等效果结束**才返回：吃/喝、盾、末影珍珠、**末影之眼（给 `bearing_deg`）**、钓鱼（抛→等咬→收）、望远镜、船/矿车 |
| 近战 | `/attack` | **追到死或超时；自动换武器、自动捡掉落** |
| 远程 | `/shoot` | 弓/弩/三叉戟；**按重力+阻力算弹道、对移动目标做提前量**；返回 `predicted_miss` |
| 合成 | `/craft` | 2×2 免工作台；`missing_ingredients` 会附 `example_recipe_needs` |
| 界面 | `/window/view` `/window/act` | **箱子、熔炉、工作台、附魔台、铁砧、砂轮、锻造台、切石机、织布机、酿造台、信标、村民**；`put/take/select/text` 四种 op |
| 装备 | `/equip` | hand / off-hand / head / torso / legs / feet |
| 姿态 | `/posture` | 全量设置；**不占动作锁**（可在 `move_to` 中途调）；`sneak` 用于搭桥 |
| 载具 | `/interact` / `/dismount` | 矿车沿轨自动行驶 |
| 丢弃 / 聊天 / 停止 | `/drop` `/chat` `/stop` | 聊天 100 字、1 条/秒、禁 `/` 开头 |

## 四、三条改架构的硬约束

### 4.1 动作互斥 + 同步阻塞 → 并发只能用来"想"

- 每个动作是一次阻塞调用，耗时 = 动作本身（走路几秒、挖一块 ~1.1 s、攻击几秒到超时）。
- 动作期间你**不能**发第二个动作（`busy`），但**可以**调 `/status`、`/events`、`/find_blocks`（不占锁）。
- 所以正确形态不是"24 个 agent 并行干活"，而是：
  **发动作 → 阻塞等 → 等的时候在另一个线程里让模型算下一步 → 动作返回时决策已经就绪。**
  动作通常 3–10 s，思考关掉后 LLM 只要 1.4–3 s，这个重叠足以把"想"的延迟藏干净。
- 24 路并发的真正用途只有两个：**分支预演**（同时评估 4 条任务路线）和**长文规划**（多个 planner 并行草拟 DAG），不是为了提速。

### 4.2 能力天花板

- **无矿透**：`find_blocks` 只给暴露方块 → 找钻石只能靠洞穴/挖探槽。`radius 64` + 摘要模式是唯一"扫描"手段。
- **无逐 tick 控制**：做不了精密时序（活塞、红石时序、精确跳跃）。
- **无鞘翅**：长途移动靠走路/船/马/下界。地图探索类 advancement 的成本被抬高。
- **不提供自动反击**：被怪打时只返回 `nearest_hostile`，要不要打是你的决策。
- **`stop_on` 默认 `["hurt","death"]`**：走路被打断会返回 `interrupted`，容易陷入"走两步被打断"的循环；`/attack` 默认只中断于 `death`，意味着**攻击中被打死也不会自动停**——安全层必须用 `/stop` 主动打断。

### 4.3 死亡循环：唯一的"一票否决"

- 60 s 内死 3 次 → 下线 **5 分钟**，且重连要等冷却（`death_loop_cooldown`）。
- 8 小时里死 6 次 = 10 分钟白给，还丢掉身上东西和位置。
- 所以**安全层的优先级高于一切计划**：血量阈值撤退、岩浆/悬崖/虚空规避、夜晚不野外、怪多就 `posture{sneak}` 或绕路、`/attack` 前先看 `health` 和 `armor_points`。

## 五、从接口反推：什么便宜、什么贵

**几乎免费的（一次调用搞定）**
- 战斗类：`/attack` 跟打到死 + 自动捡掉落；`/shoot` 自带弹道和提前量 → 骷髅、蜘蛛、苦力怕、烈焰人、末影人（注意末影人打不过）
- 末影之眼 → 直接给 `bearing_deg`，**要塞定位几乎零成本**
- 熔炉/工作台/附魔/酿造/村民交易 → `window/act` 一把梭
- 农业、养殖、钓鱼、剪羊毛、挤奶 → `interact` + `place`
- 睡觉跳夜 → `interact`（床）

**很贵的（时间线性增长）**
- 挖矿类：无矿透 + `radius 64`，钻石/远古残骸靠运气和洞穴
- 长途探索：无鞘翅，走/船/马
- 精确建造/红石：无逐 tick 控制
- 大规模收集（"一背包圆石"这类）：每块 ~1.1 s

**结构性推论（等计分表核对）**
`单项分 = 难度基础分 + 5×深度` 里，**深度项是复利的**：一条 15 级的主线链，光深度就贡献 `5×(1+2+…+15) ≈ 600` 分，而且链上每个节点都各自计分。所以：
- **推 story 主线（木→石→铁→钻→下界→烈焰棒→末影珍珠→要塞→末影龙）大概率是全场最高性价比**，因为它是唯一一条又深又长、且每步都被 API 良好支持的链。
- 散点捡便宜（浅层、难度 1）在归一化后会被稀释到接近 0。
- 战斗既然免费，**怪物猎人/狙击手这一支的性价比异常高**（浅层但基础分不低）。
- 真正的分水岭在**中后期**：钻石装、附魔、下界、末地——这些是"计划能力"而不是"操作能力"的比拼。

## 六、修正后的架构

```
                 ┌──────────── Planner（开思考，每 2–5 min，262k）
                 │   输出：任务 DAG + 当前目标 + 资源缺口
                 ▼
  events/status ─→ Tactician（关思考，每个动作一次，1–3 s）
   (不占锁轮询)      输出：下一个 API 调用 + 参数（JSON）
                 ▼
                 Executor（串行，一次一个动作，带超时/重试/降级）
                 │
                 ├─ 动作期间：并行预取下一步决策（把 LLM 延迟藏进动作耗时里）
                 └─ 失败码分类：可重试 / 需换计划 / 致命
                 ▲
              Safety（最高优先级，可抢占）
              hp<8 | 岩浆 | 虚空 | 敌对>3 | 死亡循环计数 → 强制 /stop + 撤退
```

**四条工程红线**
1. **一次动作一次调用**：RTT ~0.5 s，一个动作配 3 个观察调用就是 1.5 s 纯开销；能把 `status` 合并进决策上下文就合并（用 `/events` 增量）。
2. **空/错响应必须当失败处理**：`ok:false` 是正常返回（HTTP 200），别只看状态码。
3. **Token 会过期**（`expires_at`）：401 `invalid_token` 要能自动重登；重登会踢掉旧连接，5–10 s 才能 `ready`，要当"计划内事件"处理而不是崩溃。
4. **`ready=false` 时一切动作返回 `wrong_server`**：登录后要走代理大厅，5–15 s 才真正进服；启动流程必须轮询 `ready`，不要盲发动作。

## 七、新增待确认（按重要性）

1. **一队能不能开多个 bot？** 动作互斥是 per-bot；如果允许一队多账号（1–4 人各一个），执行吞吐直接 ×N——这是整个规则里最大的口子，必须问清。
2. **Token 有效期多久？**（`expires_at` 字段存在但没写默认 TTL）
3. **计分表什么时候发？** 现在所有策略推论都建立在"深度项复利"这个假设上，需要拿真表核对。
4. **`find_blocks` 的 `radius 64` 是硬上限吗？** 会不会在比赛服放宽？
5. **窗口表里没看到高炉/烟熏炉/制图台/讲台**——是不支持还是漏写？（高炉影响冶炼速度，间接影响进度）
6. **`/events` 的 `seq` 跨重连是否连续？** 断线重连后 `since` 还能不能接着用？
7. **v1.3.1 就是比赛锁定版吗？**（v1.3 明确说与 v1.2 不兼容、内测期不做兼容层，说明还会变）
8. **比赛服的 `protected_region` 范围**（出生点保护？）会不会挡住搭桥/建造。
9. 死亡后是否自动重生？`dead` 状态要等多久？
10. 世界种子/结构是否公布（决定能否预先算好要塞/村庄坐标）。
