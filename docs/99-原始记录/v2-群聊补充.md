## 三、我实测到的（11-12，用群里那个压测 key）

1. **模型名要写 `default`。** 群里给的字面 id `qwen3.6-35b-a3b` 现在直接 403：`This token has no access to model qwen3.6-35b-a3b`。写 `model:"default"` 才能通，而服务端回报的真实模型就是 `qwen3.6-35b-a3b`。→ 这是配置问题，得跟主办方确认正式 key 用哪个 id。
2. **它是思考模型**：返回 `message.reasoning_content` + `message.content` 两段，**思考 token 计入 `completion_tokens` 和 `max_tokens`**。
3. **`max_tokens` 给小了会静默失败**：`max_tokens:64` 时 64 个 token 全花在思考上，`finish_reason:"length"`、`content:""`。必须把 `max_tokens` 留到 ≥800～3000，并把"空 content"当重试条件。
4. **关思考的方法**：`chat_template_kwargs:{"enable_thinking":false}` **有效**（reasoning 长度 0，1.4 秒直接出答案）。顶层的 `enable_thinking:false` **无效**（照样思考 657 字符）。
5. **工具调用可用**：`finish_reason:"tool_calls"`，参数是合法 JSON。但开着思考时，一个"查时间"的调用花了 662 个 token / 24 秒。
6. **单流吞吐 ~27–28 tok/s**（662 tok / 24 s），与"30 tok/s"吻合。
7. **prompt 缓存生效**：响应里有 `prompt_tokens_details.cached_tokens > 0`。→ 固定 system prompt + 工具定义放前面，可变内容放后面。
8. **延迟极不稳定**：同一个一句话请求，实测出现 **1.3 s / 31 s / 58 s / 118 s** 四种结果。
9. **4 路并发只部分并行**：4 个请求里 2 个 1.3 秒返回，另外 2 个被排队到 31 s 和 118 s。→ 要么 24 路目前没真正给足，要么这个公共 key 正被全群压测占满。
10. 以上都在**公共压测 key**上，正式比赛理应是隔离的；但这些数字说明"并发 24 = 24 倍速度"这个假设**不能直接写进架构**。

## 四、这改变了什么（架构结论）

1. **预算治理 → 速率治理。** 不用再抠 token，但要控制"每次决策多久"。思考开 ≈ 24 秒/次；思考关 ≈ 1.4 秒/次。实时游戏里：
   - **反射层（每 1–3 秒）**：必须 `enable_thinking:false`，输出压到极短，最好直接输出动作 JSON。
   - **规划层（每 2–5 分钟）**：开思考，长上下文（可以真用上 262k），异步跑。
2. **24 并发是把"慢"藏起来的唯一手段。** 架构必须是**事件驱动 + 异步提交 + 回调执行**，不是"等模型回话再动"。24 个 in-flight 决策 = 平均 700ms 一次决策的等效节奏。
3. **空回复 = 最危险的失败模式。** 思考把 token 吃光 → content 空 → 你的状态机以为"模型没话说"。必须：`max_tokens` 留足 + 空 content 重试 + 超时降级到 thinking-off。
4. **延迟是重尾分布，必须有动作队列当缓冲。** 模型慢的时候 Agent 不能站着不动——用脚本层的"当前任务"顶着跑，模型回来再改计划。
5. **`default` 这个 id 说明网关做过模型映射**，正式环境可能再变一次。把模型 id 做成配置项，不要硬编码。

## 五、策略重算（对着计分公式）

- 计分仍是：`单项分 = 难度基础分(5/15/30/60/100) + 5×进度树深度`，`表现分 = 本人 ÷ 全场最高 × 60`。
- **脚本化自动战斗把难度 4/5（60/100 分）从"模型做不到"变成"工程做得到"**。这会集体抬高全场原始分 → 归一化的分母变大 → **靠捡便宜的难度 1/2 会被稀释到接近 0 分**。
- 结论：**必须打深树 + 打硬仗**。深树（depth 4–6）每项自带 +20～30 分，是性价比最高的部分；战斗类难度 5 是拉开差距的地方，而它恰好是脚本能解决的。
- **参考实现会把地板抬高**：大家起点接近，40 分工程评审实际是在评"你在参考实现之上加了什么"。规则没写这条 → 必须问清楚会不会因为"基于参考实现"扣分。
