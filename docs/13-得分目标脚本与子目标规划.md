## 三层执行契约

| 层 | 负责的事 | 需要的状态与输出 |
|---|---|---|
| 计分目标 | 按进度 ID 引用共享子目标和分支，维护计分资格、原始分、依赖、止损与服务器确认状态 | 确认身份、比赛时段与最新 `/advancements`。服务端返回已完成时记一笔，客户端证据用于追踪，裁判记录决定最终得分 |
| 子目标 | 把目标变成可验收的条件，如「持有 4 个可分配钻石」「工作台可达」「骷髅已被观察且有掩体」。规则和 AI 从当前有效动作中选下一脚本 | 记录需求量、替代来源、前置、时空范围、完成谓词、失败冷却与预算。一次只提交一个合法脚本，重观测后选择下一步 |
| 脚本 | 在有界范围内服务一个结果，如「装满一次空桶」「完成一笔交易」「挖出一批圆石」 | 参数使用语义物品、配方、数量、地点类别及策略枚举。返回结构化结果、动作和真实资源差量，脚本内解析坐标及实体 ID。正常动作走 `Executor`，每个阻塞动作一次 `yield`，Safety 保持抢占 |

这三层位于规划系统。仓库另有 L3 意图技能、L2 战术原语和 L1 Executor 的调用链。可由模型直接选择的脚本用 L3 契约接入，内部复用已有原语与观测方法。子目标由谓词和分支组成，同样适用于规则兜底。取消或抢占后执行姿态收尾，下次重新观察并创建技能实例。 [Harness 框架规则 §9](../AGENTS.md#9-harness-框架规则三层动作抽象) · [技能接口](../code/mcagent/skills/README.md) · [统一主循环](../code/mcagent/loop/README.md)

### 子目标状态与选择规则

| 条件类型 | 持久性及复用方式 |
|---|---|
| 经过裁判口径确认的进度 | 同一角色、本轮比赛中的一次性完成。消耗材料或死亡后，已确认的进度仍可入账 |
| 持有 `item / count`，装备 `slot / tier` | 每次选脚本时重查。任务完成后可归还借用额度，死亡、掉落、耗尽时重算。高阶工具可替代作业能力，计分触发仍逐个核对精确物品 |
| 地点、设施与路径 | 按服务器、本轮、维度和现场锚点记录地标、观测时间与安全回路。执行前复核身份、属性和可达性。放在世界的工作台、熔炉或传送门可复用，容器物资单独记账 |
| 互动、战斗、群系访问等触发 | 关联当前动作和进度 ID，保留观测或事件证据及有效窗口。客户端拿到结果后进入待确认，轮询直到服务器确认或转为待核验 |
| 地形、敌情与能力 | 结合新鲜的 `status`、库存、事件序号、现场方块/实体、装备耐久、经验和剩余时间。扫不到标为未知，支持更换观测点和冷却后复查 |

调度顺序是 **Safety → 计算待完成子目标与可分配资源 → 生成可执行脚本菜单 → AI 或规则选一步 → 复核结果并更新资源及进度**。两个目标共享前置时，排序只计算一次共享的剩余时间和材料，收益只合计未完成且有计分资格的目标。优先用满足强条件的最便宜路线，例如已有可达工作台就继续使用，钻石已经入包时直接确认并盘点靴子与镐的缺口。选择维度、分支和物资额度由程序校验，模型输出仍走技能白名单、参数校验和规则回退。

以「钻石护体」和「勇往直下」同时开放为例。看到废弃门可补且背包有 4 钻石，先做靴子，门线按已验证门框缺口备料。黑曜石只能靠开采、当前只有 3 颗钻石时，可先用 3 颗做镐开下界路线，或为 60 分靴子保留 3 颗并再找 1 颗。规则同时计算两条路径的收益、成本和时间。岩浆上涨或食物降到安全线时让出动作，回到安全点重新盘点。

### 昼夜、重生与死亡

| 规则 | 调度方式 |
|---|---|
| 昼夜标签 | 一个游戏日约 20 分钟，8 小时约 24 个昼夜，夜间窗口约 7 分钟，会反复出现。每个子目标标 `昼`、`夜` 或 `任意`，按 `/status` 的 `is_day`、`time_of_day` 过滤菜单。地下作业算 `任意`。种植、繁殖、钓鱼、找蜂巢放白天。骷髅挡箭、蜘蛛取线、狙击、第一次击杀放夜里。夜间目标在白天不强行开工，等下一个夜晚 |
| 睡眠 | 躺床会跳过当夜。当夜还有开放的夜间子目标时先做，做完或全部止损后再睡。按 A16 的 `doInsomnia` 设上限：真实时间超过 60 分钟（约 3 个游戏日）未睡时，睡眠升为高优先级，避免幻翼。只有 `two_birds_one_arrow` 启用时才放宽 |
| 重生点 | 下界、末地、试炼密室和深层矿道这类高风险长链开工前，先确认重生点在可回收物资的安全处。白天右键床也能设重生点。下界内用已充能的重生锚，和 `charge_respawn_anchor` 共用材料 |
| 死亡与掉落 | 死亡后读 `/status.last_death`。所有预留、地标句柄和装备状态都标为陈旧，已经确认的进度保留。若 A13 确认未开 `keepInventory`，生成「回收掉落」子目标，按距离、风险和掉落物 5 分钟消失时限决定去不去。下界与末地各线止损按 [团队分层 §八](11-任务性价比分层.md) 收紧一半 |
| 安全底线 | 食物、搭桥方块、火把和撤退用的一组方块按安全底线扣出，不分配给计分消费者。底线随所在维度和当前任务调整 |

### 可共用的子目标

| 谓词与参数 | 状态驱动的选脚本方式 | 共用该子目标的例子 |
|---|---|---|
| `station_ready(type, dimension)` | 现场工作站已核实可达时直接满足。背包有工作站时 `place_block`，库存能合成时 `craft_recipe`，否则提出材料子目标 | 一处熔炉供应铁锭、玻璃和铜锭。一处附魔台服务首次附魔、精准采集和穿透弩准备 |
| `item_available(item, quantity, purpose)` | 从空闲库存、现成成品、已知战利品、配方和采集分支中选。达到数量后分配到消费者，继续采集时重算差额 | 铁镐、铁甲、盾和桶共用铁源及炉批次。钻石裸露面、岩浆区和回撤线路可重复利用 |
| `tool_ready(purpose, tier, min_durability)` | 现场作业与进度物品分别核对。已有合规工具可装备或借用，有耐久下限时优先安排修理或备件 | 铁级镐用于钻石与红石。安全钻石级镐用于黑曜石、远古残骸。剪刀可用在羊毛、蜂巢、坐骑与狼铠 |
| `landmark_reachable(type, dimension)` | 命中指纹后检查入口、风险和返程，一处地标可带出多个候选。观察不足时选择有限勘察，受限则冷却换批次 | 要塞带出烈焰棒和凋灵头，堡垒带出开箱和合金物资，试炼密室带出钥匙、铜灯、旋风棒等，各自用独立判据验收 |
| `safe_encounter(entity_type, purpose)` | 按实体白名单、生命、站位、距离、弹药与掩体生成候选。远离、死亡、切维度后状态过期 | 同一只可控骷髅可先挡箭再击杀，普通骷髅且远射条件成立时还可尝试狙击。复用开阔射位与箭来源 |
| `active_portal(source_dimension, destination)` | 已激活的门可直接走。部分门框盘点缺口和落脚，未激活时安排构建、点火与确认。每穿一次记录两侧地标 | 首次入下界、后续回程与跨维度补给；末地门需求通过实际空框数分配 |

### 新旧技能对照

接入计划（队内本地文档《目标接入顺序与提示词》，未入库）的 17 步和 `goals.py` 按「一个目标配一个组合技能」写，技能名、文件名和白名单都已登记在台账里。本规划的公共脚本是这些组合技能的内部拆分，两者按下面的规则衔接：

1. **接入计划的 17 步照旧写组合技能。** 技能名、文件和测试文件以台账为准，不因本规划改名。
2. **组合技能内部调用公共脚本。** 公共脚本先以 L2 函数形式放在共享模块里，不加 `@register`，模型菜单看不到。
3. **注册条件。** 同一个公共脚本被至少两个已毕业的组合技能复用，并且离线测试覆盖条件不足、后验、抢占和恢复以后，才 `@register` 为 L3 技能，让模型直接选。这时在 `goals.py` 的 fallback 里替换对应的组合技能，并在 `docs/06` 记一条。
4. **新目标优先复用。** 17 步以外的新目标直接用已注册的公共脚本组装。只有缺少能力时才新写脚本。

## 岛体检

54 项条件计分是否开工，取决于两件事：最终计分表给不给分，岛上找没找到对应结构或群系。前者从计分表加载，岛体检只回答后者。扫描只用观察接口，不占动作锁，可以和铁器线并行。主动勘察要移动，才计入时间预算。指纹清单沿用 [推进批次 §四](10-推进批次.md)，由 `scout_island` 和 `scan_blocks` 实现。

| 时机 | 做什么 | 预算 |
|---|---|---|
| 开局 | 出生点做一次 `find_blocks` 摘要模式（半径 64），命中指纹后按类型精扫。沿 `survey_sector` 在岛内走一圈，每段重扫 | 专门勘察约 10 分钟（起步值，待标定），之后只做顺路扫描 |

## 下界计分目标

下界 20 项。要塞与堡垒先共享结构定位和回程地标，再按各自判据完成战斗、箱子或物品子目标。刷怪、交易和挖掘所得均只按已观察到的入包数量入账。猪灵交易同时检查普通及哭泣黑曜石、末影珍珠、抗火药水、光灵箭、线、石英、皮革与失水恶魂。按 1.21.11 原版交易表，珍珠为每锭 10/469 概率给 2–4 颗，长链预算按实存与随机止损处理。失水恶魂计分仍取决于赛事所列的灵魂沙峡谷条件。[1.21.11 猪灵交易数据](https://raw.githubusercontent.com/misode/mcmeta/1.21.11-data/data/minecraft/loot_table/gameplay/piglin_bartering.json)

自 Java 1.21.6 起失水恶魂可来自下界化石、猪灵交易，或用 1 灵魂沙和 8 恶魂之泪制作。放进水中即可触发相应进度。[Mojang Java 1.21.6 发布说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-6)

### 物资预留和中断后对账

1. 以最近一次可靠观测的库存和窗口为底账。每项需求绑定消费者、物品与数量，以及`消耗`、`借用`或`容器暂存`。从库存扣掉其他目标的消耗预留和安全底线，才得到当前可分配量。相同子目标下的同一可用工作站或地标可以被多个上层引用。
2. 预留在动作发出前由程序创建，脚本实际执行或取消后结算。物品从背包移入熔炉后转为窗口在途，熔炼输出验收时再转回库存。若同一批既准备了 4 锭做靴子、又准备 3 锭做镐，合计要 7 锭才能同时就绪，先做其一后也要保留剩余对应账项。
3. 超时、断线、死亡、窗口部分完成或世界换维度后立即标记观测陈旧。恢复时先重读状态和窗口，按实物、动作回执及进度确认对账。重试补欠额，判断不了实际扣耗时暂停此分支并释放已知无效的预留。计分记录保持服务器确认的状态，实物和路径按最新情况重建。
4. 共享情报设有效范围。挡箭、射击、击杀可以共享同一夜间遭遇，但射死后要寻找新目标，躺床也可能改变当夜可用窗口。先完成收益更高或更紧迫的行为，仍以血量、时间和安全退路作为门控。防止同一坐标、容器、实体句柄在失效后被反复使用。
