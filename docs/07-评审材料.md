## 三、五条"新颖性 / 稳定性"核心叙事候选（配验证闭环）

写成叙事时用这个结构：**观察到什么 → 反直觉的结论 → 因此改了什么 → 验证结果**。

1. **"动作互斥 ⇒ 并发只能用来想，不能用来做（执行-思考重叠 + 目标级异步战略）"**
   官方早期给了 24 路并发（比赛期收紧至 2 路），直觉是开多个 agent 并行干活。但规范 §0 写明同一 bot 一次只能一个动作且阻塞，
   所以真正的用法是"动作阻塞期间在另一个线程里算下一步"。→ 架构从"并行执行"改成"执行-思考重叠"：`planner/llm.py` 内置 2 路 `BoundedSemaphore` 并发闸门，`loop/strategy.py` & `loop/strategy_async.py` 实现 `--strategy llm` 目标级异步战略（仅在 8 类边界事件经 `DecisionScheduler` 异步预取 `Objective`，当拍立即由规则推进、永不阻塞等待模型）。
   **已验证（offline + `local-target`）**：`local-target` 第 2 轮 240s 冷启动（`<local_test_bot>`）累计仅耗 `1,746` tokens（按 8h 外推占输入额度 `2.5%` / 输出 `0.5%`）；**待补**：官方端点下一次动作实际时长 vs 一次决策延迟的重叠节时实测。

2. **用 `inspect.signature` 反射 + 强类型边界与脱敏上下文做决策校验，而不是手写白名单**
   模型最常见的坏输出是"发明不存在的方法"、传入布尔/NaN 参数或编造坐标/实体 ID（J17）。手写白名单会和 `client.py` 漂移，裸坐标透传则诱发模型幻觉；
   → `decision.py` 反射 `Client` 真实签名并叠加跨参数约束，`objective.py` 基于 104 项 `GoalSpec` 台账（89 计分项 / 2,730 分上限 [80.6%]）、`world_memo.py` 原子记忆（21 类指纹）与 `subgoals.py` 10 项活谓词校验战略目标，`context.py` 剥离一切裸坐标与实体 ID 且稳定控制在 `<= 2000` 字（典型 `1,085–1,283` 字）。
   **已验证（offline）**：`test_d0_core.py`、`test_api_v1311_client.py`、`test_objective_validation.py`、`test_objective_context.py`、`test_live_subgoals.py` 全绿；**待补**：官方模型真机拦下的坏决策统计。

3. **分级验证准入（`verified: offline` / `verified: live`）：既防幻觉污染，又破单账号死锁**
   第一版骨架删掉了未上真机的技能与 LLM 模块（见 `docs/06` 11-12 23:35），同时针对单皮肤站账号独占约束，
   把协议/恢复逻辑与架构契约纳入离线故障注入单测准入（`verified: offline`），把世界物理耦合技能留给真机准入（`verified: live`），并在 `feat/arch-converge-v2-agy` 上坚持“先过离线 + `local-target` 动作闭环复测，未过官方服标定不进 `main`”。
   → 仓库里每行代码要么经过确定性故障注入单测验证，要么标明 `verified: offline` 边界等待真机验收。

4. **同步 HTTP 阻塞动作的容错、脱困与 `v1.3.11` 精选恢复闭环**
   在同步 HTTP 动作接口下，`craft` / `use_item` / `window_act` 网络或服务端 `timeout` 处于"未知是否已执行"态，盲目重试会双倍消耗珍贵材料；普通互斥锁会让后台避险被长距离 `move_to` 阻塞，且无界 `move_to` 重复重试会造成 `450s` 卡死；比赛服若低于公开规范版本，首调可选接口返 `unknown_api` 会直接终止 8 小时进程。
   → 执行器在非幂等动作前采集背包快照，超时先 `/stop` 再比对快照或转 `Replan`；`Condition` + 抢占代次保证 `emergency()` 立即中断当前动作并由 L3 `emergency_escape` / L2 `escape_water_to_shore`、`escape_hazard_step` 逃生；叠加 16 RPS 三级限速、连续异步 `SafetyMonitor`、有界 `move_to` 超时禁重试、`runtime.py`/`skills/nav.py`/`loop/starter_skills.py` 移植上游 `v1.3.11` 精选恢复 4 项、可选接口 `unsupported_api` 降级与 `preflight.py` 进程/7897 代理拦截。
   **已验证（offline + `local-target` + `official`）**：`test_d0_recovery_and_preempt.py`、`test_api_v1311_client.py`、`test_loop_resilience.py`、`test_escape_water.py` 全绿；`local-target` `<local_test_bot>` 触发实机 `void_risk` 抢占成功保命；**官方真机三项故障演练 3/3 PASS**（断线重连 `63.11s`、`safe_mode` `65.2s` 冷却自愈与真实 `death_loop` 抓包、3 线程并发 401 单飞刷新 `login_calls=1`，归档 [`results/probe/fault-drills-official-20261119.json`](../results/probe/fault-drills-official-20261119.json)）。

5. **53 轮冷启动量化归因 + 架构收敛：消融“补丁膨胀”与“冷却自旋空睡”**
   复盘 `soak-cont` `ep-2108..2160` 53 轮全新冷启动日志发现 `smelt_iron` 达成率仅 `11.3%`（6/53）：原因在于无约束自动修单在 `feat/soak-autofix` 叠加 230+ 补丁，使 `starter_skills.py` 膨胀至 3,014 行且短路架空 `--llm`（`llm=0`）；`engine.py` 冷却退避占去 `59%` 时长（`15 × 76.5s`）；缺少 L2 体素缓存与清障导致单轮 `/get_block` 高达 `1,800–2,883` 次。
   → 果断止损旧修单膨胀，在 `feat/arch-converge-v2-agy` 收拢主干并给 `soak_ctl.py` 加 `--observe-only` 护栏：新增 L2 `voxel_cache`（按写操作代际失效）、`reach.py`（柱底选点、`clear_line_of_sight`、`reach_and_act`）、`world_memo.py` 原子 JSON 检查点、`engine.py` 同格冷却自旋三级升级（`local_retry -> relocate -> goal_abandoned`）与 `--strategy llm` 闭环。
   **已验证（offline + `local-target` + `official`）**：全仓离线单测 **1,421 项**（另附 `tools/local-api-bridge/test/` **11 项**网关契约单测）全绿；队内 `local-target` 第 2 轮 240.4s 冷启动（`<local_test_bot>`）0 死亡、`/dig` 33/33、`/craft` 7/7、拿 10 分（`/get_block` 压降至 551 次，Token 累计 1,746）；**官方 2h 长跑（`official-soak-20261119`）有效 `6303.9s` 达成 0 死亡 0 崩溃、`emergency_escape` 6/6，前 `124.7s` 拿下 5 项起步目标**，并将暴露的 4 环死锁与 Token 烧爆根因于 **`c03c26e` 闭环修复**（4 项零缺陷技能已升格 `verified="live"`）；**待补**：`c03c26e` 后新一轮官方对比长跑与阶段二/三 75 项 `verified="offline"` 技能的官方模拟服逐项真机复测。

## 六、两个容易被扣分的地方（自查）

1. **报告里的数字没有出处**：任何数字都要能指到 `probe/*.json`、`code/tests/` 或 `docs/06` 的某条；本地联调网关数据必须标明 `local-target`，**绝不混充官方比赛时间预算**。
2. **"我们打算做"写成"我们做了"**：没在官方服跑通就如实写"仅通过离线验证（`verified: offline`）或队内 `local-target` 闭环复测，官方真机尚未验证"（当前 `feat/arch-converge-v2-agy` 尚未合入 `main`），比含糊其辞安全得多——
   评委见过太多"预计实现"，写清楚边界反而显得可信（指南 `03` §七同样强调"尚无结果就如实写设计中/未验证"）。
